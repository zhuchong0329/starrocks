# 本地 OLAP 查询文件损坏容错：技术设计

版本：v1.2，2026-09-21。QCT-007 简化 FE 资格检查，接受已容忍损坏的诊断不保证送达。实现轮只编译和功能测试；同日按用户后续授权完成最新提交性能复验，见第 7.2 节。QCT-006 实测保留历史含义，不混入新版数据。
基线：9559176fab6e2cb885779f1e7b680133d58d6972。
配套：[需求文档](需求文档.md)、[实施规划](实施规划.md)。

## 1. 简化后的核心

本阶段只需要“本次是否容忍过损坏”这一单调标记，不再需要可用输入计数、逐输入健康矩阵、全部不可读判定或所有 BE 最终摘要屏障。标记只从 false 变为 true，不恢复，不控制其他任务调度。

正常执行仍使用原计划、缓存、并行度、JOIN/运行时过滤、EOS 和 LIMIT 取消。独立扫描允许的错误局部转为任务结束；此行为差异是容错功能本身，不授权新增完成依赖或确认等待。

全部独立输入损坏也按现有算子语义计算：明细可能零行，COUNT 可能为 0，外连接可能产生 NULL 补齐行。FE 在原完成点收到诊断才附 Warning；已容忍的损坏也可能无标识。

## 2. 分层职责

| 层 | 最小修改 |
| --- | --- |
| FE 用户查询入口 | 固定数量的资格检查；不遍历扫描源、Pipeline 支持或远端过滤；内部任务/写入/OUTFILE/短路/不支持协议仍排除 |
| BE 独立 OlapChunkSource | 仅允许的存储 Corruption 标记查询、丢弃失败 Chunk、结束自己 |
| BE 查询上下文 | 单调损坏标记；无成功读证据、逐行统计、tablet 停止集合 |
| 现有 BE 数据传输 | 将有关标记搭载数据/结束消息，不增加消息或等待 |
| 现有根结果返回 | 携带最终标记，FE 不新增诊断屏障 |
| FE 会话及输出 | 聚合一个 Warning；MySQL 最终包、SHOW WARNINGS、HTTP 末尾字段 |

具体字段和类名以实现为准。协议使用新可选字段，旧请求缺省严格。

## 3. 原流程内传播：实现审查重点

基线状态报告和结果 EOS 不天然有序，所以不采用“给最终 Profile 增加字段然后等它到达”。此前 F1 全 BE 屏障、F2 异常登记确认后才 EOF 的候选均取消。

实现选择在现有数据通道携带单调标记：

1. 本 BE 独立任务在转为 EOF 之前记录损坏。
2. 已有 Exchange 请求随数据/EOF 携带标记，接收方先合并标记再使该包数据/EOF 可见。
3. 标记不能像近似审计计数一样发送一次后清零：多个目的端、提前取消、增量统计采样都可能丢失它。损坏后应持续携带，或证明每个依赖通道都已收到。
4. 同 BE 片段可复用查询上下文；跨 BE 必须沿实际通道传播。
5. 根结果使用原有结果统计/结束消息返回标记，FE 原完成点消费，不等待其他 BE。
6. 纯 EOF、JOIN 构建侧零输出、广播/分区 Exchange、本地 passthrough、CTE、多输入和 LIMIT 需要分别测试。
7. 运行时过滤等控制路径可能越过数据依赖；不再据此排除查询，也不新增控制通道传播或禁用优化，明确接受诊断丢失。
8. 不因 FE 暂未收到报告就假定无损坏；也不等待已经无关的后台取消/收尾。

具体落点：`QueryContext` 保存查询内标记；`SinkBuffer::_try_to_send_rpc` 在每个实际目的端的数据/EOF 请求发送前携带标记；`DataStreamMgr::transmit_chunk` 在入队或发布 EOF 前合并；`QueryContext::final_query_statistic` 写入根结果的 `PQueryStatistics`。不修改 `TReportExecStatusParams`，不等待 Profile 报告。`QueryStatistics` 的标记为 sticky OR，不随增量审计计数消费；复用 protobuf 对象时显式清除旧的 false 路径字段，避免跨查询残留。

QCT-007 删除远端 Runtime Filter 的资格排除及递归检查，保留原有过滤器和计划。以上 BE 传播实现不改，仍尽力携带标记，但不承诺端到端送达。复杂计划的实际覆盖以测试记录为准，不能以代码存在代替真实跨 BE 验证。

## 4. 扫描错误边界

仅在本地独立 Reader prepare/open/get_next 调用返回 Corruption 时转换。表达式、公共 prepare、共享队列拆分、rowset 固定等错误原样传播。

prepare 出错不能直接从 ScanOperator 顶层吞掉；该层也包含共享 try_get 错误。独立 Reader 未完成初始化时必须安全进入既有 EOF/资源释放路径，不允许空指针读和不完整 Chunk 入队。

读中出错先丢弃当前 Chunk，再返回任务结束；之前入队的成功 Chunk 不回滚。缓存 lane/owner、token 和活动任务计数沿现有生命周期结束，不终止整个 ScanOperator。

## 5. FE 资格与客户端

资格只做相对计划规模 O(1) 的检查。StmtExecutor 先读取全局开关，false 时跳过类型与策略判断；保留 DefaultCoordinator instanceof 保护，通过 JobSpec.queryOptions 下发。策略保留内部任务、QueryStatement 类型、已有 isOutfileQuery、空计划/扫描/片段、首片段 ResultSink、短路、Arrow 和 HTTP raw 检查。不能仅因为 TQueryType=SELECT 就给内部查询开启。

不再检查 EXPLAIN、Session Pipeline、Fragment.canUsePipeline、扫描类型/lake/Connector 或远端过滤，不构造资格集合、不遍历执行树。EXPLAIN ANALYZE 可容错；普通 EXPLAIN 的提前返回不变。OUTFILE 复用原入口布尔值继续排除，避免不完整文件导出。混合源查询仅本地已接入 Reader 生效，纯外部源可携带无效请求标记，未接入 Reader 的错误仍严格。

每次 handleQueryStmt 执行（包括原有重试）都明确覆盖 QueryState 的本次容错状态，false 分支也写回，避免更换计划/协调器后沿用上一尝试的 true。保持原重试策略和配置读取位置，不新增重试或等待。

MySQL 聚合 Warning、最终包计数、SHOW WARNINGS 会话快照以及转发路径保持一致。严格错误优先。JDBC 实际驱动联调，不通过新增结果列实现。

QueryCorruptionWarning.beginStatement 先读取会话诊断；null 时立即返回，不做 ShowWarningStmt 类型判断或重复清空。已有诊断时仍遵循原规则：SHOW WARNINGS/ERRORS 和内部语句保留，下一条普通用户 SQL 清空。不修改 ShowWarningStmt、Warning 编号/内容或行数限制。

HTTP 只扩展标准 NDJSON 末尾 statistics 记录；关闭/被排除无额外字段。纯外部查询可能出现 partial_result=false/warnings=[]，但没有新增存储容错能力。true 表示收到诊断，false/无 Warning 不证明完整性。raw 严格。流中严格错误保持现有断连语义。

## 6. Query Cache 与范围限制

不改缓存策略或完整性，不用通用 PARTIAL 算子依赖传播实现第二阶段。单调标记仅服务本次诊断，不能保证历史缓存污染被后续查询识别。

未接入的读取路径不新增吞错；控制/诊断路径不完整不再阻止已接入本地读取容错。不绕行、不强制切换计划。第一阶段并非全盘校验、持久隔离或副本修复。

## 7. 性能影响评估

用户已调整为“尽可能小的影响”，集中评估在编码完成后，零影响证明不再是启动门槛；保持现有执行流程仍是硬约束。

| 路径 | 预计新增工作与控制 |
| --- | --- |
| OFF | FE 资格检查立即短路，不遍历计划；BE 仍有每 Chunk 的任务终止标志分支、每 Exchange 包的禁用分支，以及统计结构/最终结果中的固定标记读写。无诊断 RPC、扫描 I/O 或等待；不能声称只增加一次判断 |
| ON、健康 | QCT-007 仅固定数量的资格检查，取消扫描源/Fragment/远端过滤遍历；无历史 Warning 时提前返回。BE 每 Chunk 读任务局部标志、每 Exchange 包读查询标志不变。无成功行计数、逐 page 新检查或额外读盘；接收器创建时多一个 weak_ptr，不在健康收包时 lock |
| ON、损坏 | 单调标记更新、丢弃失败 Chunk、失败任务收尾、客户端一条有界 Warning，BE 每个被容忍的失败任务记录诊断日志；损坏状态不作为可消费增量清零，不形成同任务重试循环 |
| Exchange | 复用既有消息；必要的标记检查，损坏后少量控制字节，不新增往返 |
| MySQL | 最终 Warning 计数；仅有 Warning 才需要客户端读取详情 |
| HTTP | 每 SQL 末尾少量字段；不添加逐行字段 |
| 其他查询 | 诊断占用 CPU/网络/共享资源，需要故障并发测试 |

新增原子读取、字段布局、条件分支和序列化都不是物理零成本，不能用“不新增锁”或“不新增 RPC”宣称零回退。不要每 Chunk 更新共享成功计数；不新增等待、预校验 I/O、计划改写、缓存绕过或强制慢路径。

关闭开关也不等于代码二进制与基线完全一样：查询上下文、统计对象和接收器增加少量固定字段；会话开始/复用时清理上一次诊断。因此 A 原版与 B 新版 OFF 必须实测，不能只测 B/C。上述成本来自当前实现审查，不是性能测量值。

故障后继续完成查询与原版立即报错的工作量不同，分别衡量诊断成本、健康请求干扰和业务成功率。

QCT-006 对照 A=原版、B=新 OFF、C=新 ON。小 LIMIT、空结果、点查/短路、缓存命中、全扫描、冷热页缓存、多 BE JOIN、饱和并发均关注首行/完成时延、P99、吞吐、CPU/内存/RPC。保持硬件、编译参数、数据、计划一致；先报告噪声、原始样本和环境局限。发现明显回退要定位优化，不自行编造验收阈值或声称未测项目通过。

### 7.1 实测结果及不能忽略的代价

本节仅为 QCT-006 / 45cacacf0 的历史测量，不将其算作 QCT-007 验收，也不因代码删除遍历就宣称时延或吞吐已改善。后续授权的新提交 OFF/ON 实测单独列在第 7.2 节。

完整方法、逐轮吞吐、分位数、CPU 排查及证据见 [QCT-006 性能评估](QCT-006-性能评估.md)。实际有效 A/B/C 对照共 **343,512 条 SQL**，所有已测计划摘要一致、健康结果无 Warning。包括两轮完整矩阵、两轮长预热重点查询、两轮 BE 页缓存关闭对照及少量进程重启首轮；没有把进程重启或 BE 页缓存关闭冒称为 OS 冷盘。

长预热、BE 页缓存 ON、Query Cache OFF、并发 1，完成时间中位数（ms）：

| 查询 | A 原版 | B OFF | C ON |
| --- | ---: | ---: | ---: |
| MySQL LIMIT 10 | 5.813 | 5.634 | 5.958 |
| MySQL 空结果 | 6.713 | 6.449 | 6.771 |
| MySQL 倒序 LIMIT 1000 | 15.801 | 15.456 | 16.023 |
| HTTP LIMIT 10 | 4.501 | 4.603 | 4.608 |
| HTTP 空结果 | 4.983 | 5.075 | 5.085 |
| HTTP 倒序 LIMIT 1000 | 15.246 | 15.458 | 15.460 |

上述六种场景 C 相对 A 约增加 0.058～0.222 ms，不是普遍上界。**并发尾延迟不能据此忽略**：重点 MySQL、并发 4、Query Cache OFF，两轮 C 吞吐比 A 低约 3.4% / 7.1%，合并明细页 P99 为 87.204 ms，A 为 76.469 ms。其他子组并非都回退，所有数字和失败/复测记录均保留，不只挑较快结果。

BE 页缓存关闭组首轮并发约 -6.9%，反向且加长预热后约 -0.3%；单请求仍有差异。主矩阵部分并发组接近 6 核配额，另有客户端、JIT 和共享 VM 扰动，但不能把全部差异未经证明归为噪声。FE JFR 的 1,277 个执行样本未采到容错资格判断/Warning 栈，未发现新增重型检查；这不是微小开销为零的证明。未为追求某个分数改变执行计划、关闭优化或新增同步等待。

故障并发两组有界回归中健康结果均正确、没有串 Warning；充分预热后仍有运行顺序趋势，因此不以更快的中间阶段宣称故障没有资源成本。

**阶段一性能评估完成，不作无回退保证。** 当前方案的已知新增工作仍是固定资格/标志/协议成本，没有新增逐行/逐 page 工作。生产真实数据、机器、并发与 SLO 需单独复核；没有擅自规定一个百分比通过线。Query Cache 完整性仍留在第二阶段。

### 7.2 QCT-007 最新提交复验

用户后续授权后，针对实际提交 `46ca14950` 重新增量打包 FE/BE、运行 41 项 FE 与 46 项工具回归，再按原参数完整重跑 A=社区基线、B=最新 OFF、C=最新 ON，另补两轮页缓存关闭异常复测。共 361,512 条有效健康对照；22 类计划、tablet 放置/版本、B/C 产物和 1,266 个规范化编译命令均核验一致。没有为测量修改业务代码、计划、等待或缓存策略。

**仍存在正常查询的局部性能回退，不能认为常量时间资格判断等于端到端零影响。** 长预热日志检索六类单请求的 C/A 合并 P50 低约 2.7%～6.5%，但 MySQL/Query Cache OFF/并发 4 的混合 QPS 两轮为 +7.35%/-5.19%，方向不稳定；分页合并 P99 从 A 75.024 ms 升至 B 83.653 ms、C 90.921 ms。完整扫描/聚合/JOIN 混合负载同条件下 C/A 吞吐两轮为 -1.15%/-3.39%。不能用更好的 P50 掩盖 P99，也不能将全部差异未经定位就归给 isEligible 或环境噪声。

页缓存 OFF 首轮并发 -15.23% 的异常保留；长预热和两轮同参数复验分别为 -1.49%/+0.06%/+2.63%，未稳定复现同幅度。故障并发首次发生健康连接包序号错误，日志关联 BE 重启后的取消/重试，根因尚未闭环；不改代码原样复跑通过，文件均恢复。无新增 OOM，所有测试节点停止，缓存和 Tenant-TTL 未受改动。

完整逐轮时延/吞吐、首次失败、未覆盖项和证据见 [QCT-007 性能评估](QCT-007-性能评估.md)。本次没有同时运行旧功能代码 D 组，不能跨日期定量归因 QCT-007 的优化收益；没有设置未经批准的通过阈值或声称生产 SLO 已认证。
