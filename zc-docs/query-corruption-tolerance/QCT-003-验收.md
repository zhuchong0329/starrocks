# QCT-003：既有通道的损坏标识传播

日期：2026-09-19。BE 聚焦回归通过；真实跨 BE 文件故障仍属于 QCT-006。

## 实现

- 查询上下文保存单调诊断。`QueryStatistics` 按 OR 合并，标识不随 audit delta 被消费；序列化复用 PB 时会清除上一查询遗留的字段。
- 已启用容错的 `SinkBuffer` 在原本实际发送的数据／EOF 消息中附加 true 标识，覆盖多目的端和纯 EOF，不依赖抽样 audit statistics。
- 接收器创建时捕获独立 weak query context，在发布收到的数据／EOF 之前合并标识；不依赖之后才发生的 `attach_query_ctx`，避免接收注册后的生命周期竞争。
- 根结果沿原 `final_query_statistic` 返回诊断。不新增 RPC、确认、等待、取消或完成流程。

## 实际验证

专属 arm64 / GCC 12.3 / Release BE_TEST 构建与最终增量链接成功。测试进程文件句柄软上限 65535；没有与大 C++ 编译并行运行 Maven。

- `QueryStatisticsTest` 3 项（2 原有、1 新增）：可选字段、sticky OR、多接收者、重复聚合、clear 和 PB 复用。
- `ExchangePassThroughTest` 6 项（3 原有、3 新增）：原 pass-through/背压/关闭；未 attach 时纯 EOF 已可见；严格接收器不接纳；真实 SinkBuffer 的两个目的端、5 个既有包、纯 EOF、关闭审计采样后仍传递、取消后无额外 RPC。
- 上述 9 项全部通过；联合扫描测试共 14 项，随机顺序重复 20 轮全部通过（280 次执行，非 280 个独立用例），exit 0。
- 修改 C++ 的语法检查及 clang-format-14 改动行检查通过。
