# 本地 OLAP 查询文件损坏容错：需求文档

版本：v1.0，2026-09-19，需求已对齐并获授权开始 QCT-001～006。本文取代此前全部不可读保护和零性能影响要求。

基线：本地 4.0.11，提交 9559176fab6e2cb885779f1e7b680133d58d6972。
工作分支：codex/query-corruption-tolerance。
配套：[设计文档](设计文档.md)、[实施规划](实施规划.md)、[环境隔离约束](../../AGENTS.md)。

## 1. 最新确认

1. enable_query_corruption_tolerance 的代码默认值为 false；最终产品 conf/fe.conf 设置 true。
2. 仅面向用户发起、读取本地 shared-nothing OLAP 表的只读 SELECT。
3. 第一阶段只处理独立扫描任务的本地文件物理 Corruption；公共准备、共享任务严格报错。
4. 同 tablet 的其他并行任务独立运行，不建立 tablet 级共享停止标记。
5. 单侧全部损坏、整条查询全部不可读，都允许继续按剩余输入计算并返回 Warning，不再因缺少可用输入报错。
6. MySQL/JDBC 使用 Warning，不新增 SELECT 结果列或附加结果集。
7. 标准 HTTP SQL 在同一阶段后续轮次支持，末尾 statistics 记录增加 partial_result 和 warnings。
8. 未接入路径保持现有执行路径和严格错误行为，包括短路/非 Pipeline、HTTP raw、混合本地 OLAP 与外部表查询。
9. 第一阶段不改变 Query Cache 命中、写入或淘汰逻辑；B 方案列入第二阶段。
10. 不改变查询计划、调度、EOS、LIMIT 提前结束和取消流程；不为诊断新增同步等待、确认往返或完成屏障。
11. 性能目标是尽可能小的影响，不再要求绝对零影响；集中性能评估在编码完成之后进行，不作为启动编码的前置门槛。
12. 用户已授权连续实施到 QCT-006；每轮完成必要确认测试、单元测试及验收后独立提交并推送 origin，不自动发 PR。

## 2. 适用范围

本地 OLAP 包括 Duplicate/Aggregate/Unique/Primary Key 表，但不是全部分析型数据源。视图、CTE、子查询按展开后的实际扫描源判断。

支持路径可以有过滤、投影、聚合、排序、LIMIT、JOIN 和多输入组合。查询内部的全部数据流路径必须已接入诊断传播；无法保证的路径保持严格执行并公开覆盖限制，不修改计划来适配容错。

不启用：写入语句、INSERT SELECT、CTAS、UPDATE、DELETE、导入/导出、SELECT INTO OUTFILE、统计收集、内部查询、物化视图刷新、clone、compaction、checksum 任务、EXPLAIN ANALYZE、Arrow Flight、lake、外部 Connector，以及未接入路径。

混合本地和非本地扫描源的查询整体保持严格，不局部开启。

## 3. 错误边界与任务收尾

只处理开关实际生效且源自独立本地 Reader prepare/open/get_next 的物理 Corruption，例如 checksum mismatch、segment magic/footer 损坏。不是通过错误字符串包含 corrupt 来判断，也不是在通用错误处理层吞掉全部 Corruption。

普通文件缺失、版本缺失、一般 I/O、权限、网络、OOM、超时、取消、表达式错误继续原错误行为。

独立任务遇损坏时：

- 标记本次发生容错，保留此前成功送出的 Chunk。
- 丢弃当前失败读取的整个 Chunk，即使已经填入部分数据。
- 当前任务以原有结束机制结束，放弃其剩余范围；不在同一 Reader 内搜索下一个完好 page。
- 释放 Reader、token、active input 等，避免重复调度、卡住或资源泄漏。
- 同 tablet 的其他任务不受连带停止影响，可以分别再次遇错。

公共 prepare、rowset 固定、共享 morsel 拆分/索引加载等保持严格，不移动共享逻辑来扩大覆盖面。不自动修复文件、切副本、标 BAD 或跨查询隔离。

## 4. 结果语义

| 场景 | 约定 |
| --- | --- |
| 未遇到被容忍的损坏 | 普通成功，不产生本功能 Warning；不是全盘健康认证 |
| 部分任务损坏 | 基于剩余输入计算，结果 + Warning |
| LEFT JOIN B 全坏、A 可用 | 允许 NULL 补齐行 + Warning |
| INNER JOIN 单侧全坏 | 允许零行 + Warning |
| 所有独立扫描输入都损坏 | 允许空结果或算子生成结果（如 COUNT=0）+ Warning，不新增全坏错误 |
| 公共/共享阶段或非容错错误 | 沿现有流程报错，不用 Warning 覆盖严格错误 |

结果可能不完整、不准确，不保证是完整结果的简单子集。聚合、外连接、反连接、排序分页均有此限制。

LIMIT 满足后按原流程完成并取消不再需要的工作，不等待所有 BE 收尾，不继续校验未读取范围。实际参与本次容错计算的标记需要随既有通道传递；完成后后台取消/收尾才发现的损坏不追溯结果。不得依赖延迟到达的异步 Profile 冒充可靠标识。

保持流式返回，严格错误发生前已发送的行不能撤回；客户端须检查最终状态。

## 5. MySQL/JDBC

部分成功在最终 EOF/实际协商结束包中携带非零 Warning 数量，并支持同一会话 SHOW WARNINGS 和 JDBC Statement.getWarnings()。

建议聚合为一个 SR_QUERY_PARTIAL_RESULT，数字码在实现时检查分配。提示说明结果可能不完整、不准确，附 query ID；不要求精确失败任务数或丢失行数，不暴露文件绝对路径。

SHOW WARNINGS 不能在读取前清空上一条诊断，下一条普通 SQL 不能继承旧 Warning，连接复用不能串会话。客户端需在消费结果后、归还连接池前提取 Warning。健康查询不要求额外 SHOW WARNINGS 往返。

FE 转发和 prepared/text 协议均需验证，未验证项如实记录。

## 6. HTTP SQL

标准 NDJSON 的现有末尾统计记录增加同级 partial_result / warnings；不改 meta、data 或用户列。例如：

    {"statistics":{"returnRows":0},"partial_result":true,"warnings":[{"code":"SR_QUERY_PARTIAL_RESULT","message":"Result may be incomplete or inaccurate"}]}

只为实际启用容错的查询增加字段，未遇损坏时 false，关闭/不适用时保持旧格式。false 不是物理完整性认证。

HTTP raw 模式不启用容错。严格错误沿现有发送前错误响应、发送后断连路径；客户端不能只凭 HTTP 200 成功，必须完整收到末尾记录及正常结束。

HTTP 与 MySQL 同属第一阶段，先 MySQL 后 HTTP，不新增完成等待。

## 7. Query Cache

本阶段沿用当前策略，不绕过缓存，不新增部分结果 populate 保护，不传播完整性到所有算子。仍需保证既有 lane/owner 完成通知与资源释放正确。

已接受风险：部分结果可能污染 Query Cache；后续即使关闭容错，也可能命中历史不完整值而没有 Warning。缓存命中不是读盘验证。基线 enable_query_cache 初始 false，实际会话可能覆盖；测试分别覆盖开/关。

第二阶段 B 方案再处理 JOIN、Exchange、运行时过滤等依赖的完整性、缓存写入时序及历史污染缓存。

## 8. 配置与部署

FE 启动配置在每次用户查询中形成快照，再通过可选 query option 下发；缺省为 false。第一阶段同版本 FE/BE 部署，滚动升级保持 false。

验收后产品 conf/fe.conf 加入：

    enable_query_corruption_tolerance = true

代码默认仍 false。已有部署需同步每台 FE 实际配置并使其生效；不承诺热更新。关闭只影响后续查询，不修复文件或清理缓存污染。

## 9. 验收与交付

每轮必须记录实际测试、通过/失败和未测原因，不能以静态检查代替编译或故障验证。覆盖独立初始化与读中损坏、失败 Chunk、同 tablet 并行、全部损坏、JOIN、空结果、LIMIT、取消、严格错误、开关关闭、协议与会话生命周期。

QCT-006 集中真实文件故障及性能评估。对照原版 4.0.11、新版 OFF、新版 ON；记录计划、扫描量、首行/完成时间、P50/P95/P99、吞吐和资源。不宣称绝对零成本，不预设用户未批准的百分比通过线；异常处理工作量与健康路径性能分开报告。

所有环境和测试数据与 Tenant-TTL 隔离，保存编译缓存。不能把未跑过的集成测试、驱动验证或性能评估写成已验收。
