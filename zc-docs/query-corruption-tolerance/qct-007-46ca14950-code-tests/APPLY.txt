预期只有 qct-007-46ca14950-code-tests/ 下的 patch、清单和说明，无源码全集、缓存或旧补丁包。
如果目标目录已存在，换到新的解压目录；不要覆盖以前的内容。

for qct_state in rebase-apply rebase-merge MERGE_HEAD CHERRY_PICK_HEAD REVERT_HEAD; do

本次不需要再次 git add/git commit；git am 已经创建提交。

5. 失败与冲突处理

如果 --check 失败，不进入 am；先查看目标文件与补丁上下文。
若确认差异可合并且内网已有补丁 index 中对应的基线 blob，可选择三方应用：

git am --keep --3way "$qct_patch_dir/0001-perf-query-corruption-QCT-007-simplify-query-opt-in-.patch"

--3way 不是自动消除冲突；缺少基线 blob 时仍会失败，也不会自动访问外网补对象。
若已经有失败的 am 进行中，不要直接重复上面的 git am 命令；先选择解决或 abort。

git status
git am --show-current-patch=diff

人工解决后，只 git add 实际已核对的冲突文件，例如：

git add fe/fe-core/src/main/java/com/starrocks/qe/QueryCorruptionPolicy.java
git am --continue

如果还存在其他冲突，必须逐项解决并显式添加后才 continue，不使用 git add . 混入无关变更。
如果决定放弃当前这批导入：

git am --abort

--abort 会撤销本次 am 批次已应用的提交及冲突处理，回到这次 am 开始前的状态，所以必须在干净工作区启动 am。本包只有一个提交。
不要默认 git am --skip，否则会漏掉本次功能；不要用 git reset --hard 清理用户工作。
注意：成功完成 am 后不存在进行中的批次，--abort 不用于撤销已完成提交。若之后决定撤销，应按内部流程使用 git revert 并核查依赖。
