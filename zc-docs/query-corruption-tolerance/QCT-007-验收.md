## 1. 已确认与实现

- EXPLAIN 不再专门排除，包括会真正执行的 EXPLAIN ANALYZE；普通 EXPLAIN 的提前返回保持原样。
- OUTFILE 保持排除，复用 StmtExecutor 已计算的 isOutfileQuery。DefaultCoordinator instanceof 保留，全局配置移到前面短路。
- 删除 Session Pipeline、Fragment.canUsePipeline、扫描源类型/lake/Connector 和远端 Runtime Filter 的资格判断。不存在扫描源循环、片段循环或递归执行树遍历；剩余检查相对计划规模为 O(1)。
- 混合查询中仅已有 BE 接入点可容错，纯外部查询可携带无效开关；不扩大实际吞错范围，不修改执行模式、计划、调度、EOS、LIMIT、取消或缓存。
- 已容忍损坏的诊断也只尽力传递。HTTP false/空 warnings 不证明完整性或读取路径支持；纯外部查询可能出现这两个字段。
- 每次原有查询尝试明确更新 FE 容错状态，避免更换计划/协调器后继承上次 true；不新增重试。
- beginStatement 无历史 Warning 时提前返回，不做 ShowWarningStmt 类型判断和重复清空。有诊断时原保留/清理规则不变，ShowWarningStmt 未修改。

生产文件仅 `QueryCorruptionPolicy.java`、`StmtExecutor.java`、`QueryCorruptionWarning.java`；测试文件仅 `QueryCorruptionPolicyTest.java`、`QueryCorruptionWarningTest.java`、`QueryCorruptionPlanTest.java`。BE、协议定义、缓存、配置模板均未改。
