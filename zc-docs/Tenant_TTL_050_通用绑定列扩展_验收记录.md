## 3. 真实集群及数据判定

复用隔离集群 `sr-ttl-r043` 的 3 FE / 3 BE 与原持久卷，安装新的版本化二进制副本，不覆盖旧 043 产物。脚本与运行说明见 [generic_binding](../test/sql/test_tenant_ttl_compaction/generic_binding/README.md)。完整输入、明细、Profile、状态和日志保存在该目录的 ignored `artifacts/`，通过结果另整理为可提交的索引。

正常场景每表 12 个时间分区、每分区 4 Tablet、每 Tablet 3 副本；两表完全没有 `tenant`，分别绑定 `dst_ip` 和 `device`，共用第一键名为 `policy_value` 的 Dictionary。双方 VARCHAR 宽度不同。每表分别准备 120,000 / 1,200,000 行，覆盖 1,000 类值、空字符串、空格、大小写、`001`/`1`、文本 IP、Unicode、未命中、NULL 及重复行。

同表两候选列的值错位分布：它们的最终行数相同，但应保留的具体行不同，完整多重集合比对可以识别误用绑定列。

独立 oracle 按分区上界与实际策略计算行多重集合。每个保留 Tablet 的全部副本使用定向 SQL 读取完整业务列，并以 EXPLAIN 和实际扫描 Profile 证明读取目标；另外全表扫描排除遗漏分区或错放数据。部分重写保留 NULL，整分区过期可删除 NULL。COUNT/MIN/MAX 缓存值不作为 oracle，未绑定对照表必须保留。

自动分区中的空 shadow/default 分区仍不可证明，SHOW 可保留 `DEFAULT_OR_MISSING_LIST_VALUES` / `FAIL_CLOSED` 诊断；本次没有放宽其清理准入。有数据的可证明分区仍独立执行，验收要求其全部副本完成并通过完整行比对，不将该已有空分区诊断误记为整个扩展不可用，也不隐藏诊断。
